## Persistence, retry and renewal

- Add Frank-owned tables transactionally without rehashing existing event/delivery rows. Legacy records and LocalDevResults(None) keep their existing full-result identity. Existing exact runtime command bodies remain immutable.
- Native result identity is immutable unsigned result digest plus exact retained work digest, bound to effect key and transport event. First observed original result bytes remain retained; each separately verified proof is append-only authority evidence.
- Replay key stable-subject/session/opcode/nonce binds exact holder/verifier key, whole native packet/context/proof, work/result identity and effect key. Exact repeat admission is idempotent after restart; reuse with changed any binding is rejected. New attestation uses a new nonce and can only renew authority for the same immutable unsigned result and work.
- Admit replay, native identity, proof evidence, event and terminal observation in one BEGIN IMMEDIATE transaction. Failed observation/revalidation rolls back the nonce. Reverification before complete/fail and uncertain completion/failure reconciliation must perform durable revalidation before any Runtime terminal command. No ledger consumption during an isolated verifier-only check.
- For native deliveries, observation_digest and exact effect-observe command request_id derive from the immutable unsigned result identity so renewal cannot change an already committed effect observation. Legacy command digests stay unchanged.
- Journal.get may project the latest admitted proof over unchanged retained result body for current verification, while retaining the first result and append-only proofs in storage. Proof update must never alter original outputs/provider/event/outcome.
- Receive checks terminal native result authority before advancing cursor, including duplicate pages; all potentially blocking helper/policy checks finish before one shared latest-time, no-I/O window check for every native result under the cursor writer transaction; changed proof is only admitted for identical body/work after full native verification. Expired/unavailable/revoked proof blocks unconfirmed terminal operations and cursor advancement; never resend. Already confirmed durable history is preserved, not erased or rewritten by revocation.
- Readiness, Matrix/Hermes production compatibility, real issuer/attestation producer and qualification remain incomplete. Existing Matrix normalization changes transport fields; attestation must occur after normalization or use a separately versioned reviewed actor/provenance split. Do not omit those fields.

## Reviewed dispatch repair and implementation port

- Mandatory guard covers terminal execute and exact replay after every local attempt-lock and command-authority wait. Guard revalidates/adopts the NativeResultAdmission inside BEGIN IMMEDIATE, binding the exact retained command digest and delivery identity immediately before actual transport dispatch. If the installed SDK adapter moves execution to a worker thread, run this guard within that worker immediately before SDK.execute. Native result terminal execution rejects any client transport without this guarded-dispatch interface. Legacy calls with no admission guard retain the existing client signature.
- Public verifier token interface for the coordinated Journal implementation: NativeResultAdmission.identity is unsigned result SHA256; work_sha256; proof (decoded closed native envelope, fresh copied JSON); replay_key=(subject_id,session_hex,opcode,nonce_hex); replay_digest binds subject/holder/verifier-public-key fingerprint, work/body/native packet/context/proof digests. revalidate(result,work) reads current immutable policy and current clock and checks exact proof/body/work plus helper pin. All dataclass policy fields including verifier public-key bytes are compared, never only key_id. Tokens are immutable and cannot be reconstructed from caller JSON.
- Journal APIs may take keyword admission=None for observation. Add reauthorize(key,result,admission,command=None) for durable exact proof renewal/dispatch admission; result_digest(key,result) chooses existing legacy full digest or verified native immutable body identity without silently upgrading legacy records. Journal.get returns latest admitted proof projection; retained first delivery.result bytes are never rewritten. Reauthorization on new key/unsigned body/state cannot upgrade or replace a legacy terminal result.

## Package and repeatable verification

`native_results.py` uses only Frank model utilities, Python standard library and the public verification-only executable wire protocol. `FileReceiverPolicy` reloads a closed owner-private public configuration; `ReceiverPolicy.snapshot()` provides its exact serializable format. The additive frank-local-review loader accepts only closed pinned owner composition; no production qualification toggle is added. Changing the built-in verifier mode string cannot admit it: production requires its exact native helper, current private-file policy, real system clock and a concrete Wallet call authority. Existing `frank.config.v1`, work/result schemas and legacy Journal records retain their original shape. The optional native profile ships as `contracts/native-result-authority-v1.schema.json`.

Public native tests require an actual verification-only helper. Set
`FRANK_NATIVE_VERIFIER` and an independently recorded `FRANK_NATIVE_VERIFIER_SHA256`;
the historical macOS digest is the fallback test pin. The helper's source/lock and
artifact digest must be recorded. Public vectors and the non-shipped cfg(test)
generator are retained under `tests/fixtures/native-result-public` and
`tests/native-fixture-generator`; the historical generator lock has the anonymous
regeneration limitation described in [verification](verification.md). Missing
helper is a test failure, not a skipped native check. Final policy time checks run after the last policy/artifact reload. Cursor admission uses `current_time()` and `revalidate_window(result, work, now)` only after full per-result revalidation: these bounded no-I/O methods check exact body/work/proof and the captured policy window at a shared post-I/O time. They do not replace cryptographic verification or current-policy reload. A failed final batch check rolls back proof, replay and cursor changes together.

The portable profile is checked against success, renewed-proof and failure fixtures. Identifiers and native hex reject trailing newlines; unsigned payloads reject embedded proof; failed results reject output fields. Existing public work/result schemas and legacy decoders remain unchanged.
