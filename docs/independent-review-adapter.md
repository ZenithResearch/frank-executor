# Independent review adapter

`frank_review_adapter` is a separate capability-selected package conforming to `IntegrationAdapter`, `Registry` and `Executor`. Register its factory as an extra plugin; no dispatcher, scheduler, runtime storage or legacy executor code is changed or imported. The runtime's `work.list`, claim, lease, output and receipt contracts remain authoritative. Every fixture work packet is checked against its live public runtime claim before computation.

The nine review capabilities freshly load immutable asset bytes, consume an explicitly injected frozen STT response, resolve exact source selectors, annotate verbatim speech with separate timing evidence, extract bounded speech observations, inspect source, publish an immutable final packet/document, and compute simulated status and daily-note intents. Expected legacy output values are comparison-only data loaded after independent execution. They are never handler inputs.

All ports are explicit and effect-disabled. Synthetic artifact, STT, component, source, claim, result and intent ports have no vault, provider, credential, arbitrary URI or host codebase reader. Fixture source inspection operates on injected in-memory strings. Artifacts verify both digest and byte length. The public artifact bridge only reads/writes the disposable runtime's content-addressed artifact API.

Only timed reviewer speech becomes feedback. Repeated target occurrences are matched individually against their overlapping word windows; a later silent gesture stays negative evidence. Missing word timing, unresolved component names or absent source matches preserve quotes and uncertainty. A bounded lexical detector is disclosed as unqualified analysis; it cannot manufacture design requirements, causes, fixes or acceptance criteria. The frozen normalized event type omits raw geometry. Root input artifacts and receipt provenance retain that evidence, and packets explicitly require inspection before geometry-dependent inference.

Step 5's initial packet is immutable. Its handoff retains the explicit no-ISS-creation, no-fix-execution and no-unstated-redesign constraints alongside the existing anti-inference rules. Each observation has a binding-pending note and an implementation-cause limitation, separate from the global fixture qualification note. Step 7 reads that packet, preserves its full negative ledger and raw observation/quote/evidence values, binds inspected source evidence and creates a different final content-addressed packet. Final notes replace pending diagnostics with verified-location-only, deferred or blocked reasons for each observation; v2 semantic metadata separately reports contradictory component/reference locations as source-conflicting. An unresolved target blocks location binding; unavailable source for an otherwise resolved target stays deferred. Step 8 rereads the final bytes and recomputes quality before any status intent. A missing, unreadable, malformed, transcript-only, unresolved or source-deferred packet fails its Attempt; downstream daily-note work remains non-runnable. The runtime represents those downstream steps as `waiting` under the failed run rather than inventing a different state.

`review_packet_ready` remains the existing source-evidence/processing predicate, separate from v2 semantic planning eligibility. New canonical extraction emits `review.independent-packet.v2` under the unchanged `{effects, route}` adapter configuration. Its closed `semantic_metadata.observations` map is keyed by exact observation IDs and records feedback as record kind, layout/unknown issue category with a disclosed finite basis, unassessed semantic confidence, separate source-evidence scope/state and typed per-item triage. The metadata is inside the artifact; all closed observation/context ports, quality strings and string-list buckets remain unchanged.

The named `review.bounded-layout-planning.v1` policy recognizes full coherent centering/alignment assertions or affirmative directives. A bounded action/subject lexical cue retains uncertain alignment speech for inspection without admitting it to the complete-utterance planning grammar; fragment and silent-event exclusions remain. Only complete finite preference, praise and correct-state utterances receive those negative classes; questions, incomplete or negated/contradictory intent remain ineligible; a category keyword alone cannot confer eligibility. Initial clear concerns remain source-pending. A final `planning_eligible` decision requires the supported concern, one resolved selector and exactly one consistent verified source reference whose supplied path/line exactly matches the retained resolved component source pointer. This is inert data comparison, with no file access or provenance inference. Structured finite action/goal rules reject opposing directions, same-goal refusals and opposing exact correct-state assertions; compatible repeated directions and generic praise can coexist with a concern. Explicit refusals remain retained negative-intent observations. Unrecognized compounds remain unsupported rather than being classified by a preference or praise substring. The closed `layout_action` record exposes only the finite request/refusal/concern/correct-state kind and normalized goal used for conflict checks. It enters `actionable_now` for planning only, leaves clarification and has no stale generic open question. Preference and explicit non-issue have their own ID buckets; unsupported intent, unresolved target, unavailable mapping and conflicting candidates retain distinct blockers. General verbal concerns without gestures remain representable. Fragments and silent gestures remain negative evidence. No issue creation, fix, task issuance, provider effect, authority or per-review human approval event follows any bucket.

## Explicit packet inspection

`frank-review-packet` (or `python -m frank_review_adapter.packet_reader`) is a separate read-only consumer. The API requires the keyword `packet_format`; the CLI requires an explicit matching `--format review.independent-packet.v1` or `--format review.independent-packet.v2`. `PACKET_FORMAT` remains the v1 API constant; `PACKET_FORMAT_V2` names the new profile. No format is autodetected. Legacy `schema_version=2` bodies, unrecognized discriminators/statuses/types, malformed observation identities, dangling event/source links, and malformed reference records are rejected. No packet is translated to legacy `feedback_items`, `source_bindings` or `quality.status`, and no Hub/executor/Runtime routing changes are implied.

```sh
frank-review-packet --format review.independent-packet.v2 --packet /absolute/path/to/v2-packet.json
frank-review-packet --format review.independent-packet.v1 --packet /absolute/path/to/stored-v1-packet.json
```

The command reads only the explicit input (at most 1 MiB plus the overflow sentinel) and prints JSON inspection data. `inspect_packet(raw, *, packet_format, expected_reference=None)` reads no files. Its optional exact `{content_hash, byte_length, media_type}` comparison binds the supplied raw bytes to a content reference; neither that comparison nor reader admission authenticates their producer or history. The output keeps the unchanged parsed producer object under `packet` and a separate `review.packet-inspection.v1` view. It preserves the string quality label, reported feedback type, raw quote/issue, target, decoded evidence with exact `linked_event_indices` containing `event_index` identifiers resolved against the unchanged `packet.events` records (not list offsets), source records/references, binding reasons, confidence strings, notes, uncertainties, non-goals and complete negative ledger. Initial and final blobs retain their distinct raw SHA256/size; `review_metadata_present` describes metadata presence rather than an authenticated stage. Review metadata strings are display data, not command principals; observation IDs use the existing bounded identity syntax and source/event correlations must resolve.

The retained v1 profile keeps its existing object keys and string/list ports. V2 additionally validates exact metadata coverage, policy/scope/stage, quote/event/source correlations, recomputed per-item decisions, noncontradictory buckets and stage-specific reasons. V2 quality is recomputed for inspection; a supplied eligibility or quality flag is never authority. Evidence and source-reference strings must contain their current JSON record shapes. A reference has string `path`, `selector`, `text`, positive integer `line` and lowercase SHA256 `content_hash`. Reference paths/URLs remain inert text: the reader never opens, resolves or fetches them, including handoff file references. Negative evidence, task and diagnostic strings remain exact opaque strings, without guessed schemas or execution. This is JSON display, not an HTML/Markdown renderer; a downstream UI must use its own admitted inert rendering boundary.

The retained v1 profile admits the current quality labels, `feedback` observation type, the two current target-match states, resolved/unresolved component states, verified/deferred/blocked source states, and unchanged `source_match_only`/`low` confidence strings. Unknown values are unsupported, not mapped to new vocabulary. Domain dimensions absent from packet-v1 are explicitly marked missing: issue category, confidence basis, typed triage decision/reason, semantic eligibility policy and root input artifact references. No raw geometry, provenance link or semantic decision is reconstructed from the transcript or another field. Event bodies occur once under `packet.events`; per-observation views carry only event indices so a large shared event is not copied for every observation. Per-observation source/diagnostic text stays reported text; missing source context is marked missing. `review_packet_ready`, historical `actionable_now` entries and source-match confidence never authorize implementation or effects.

## Process resource provenance

`--require-installed` resolves the frozen process resources from the exact installed `process-runtime==0.1.0` distribution, using its file records and this interpreter's `sysconfig` data root (`share/process-runtime/resources`). It requires a unique matching Runtime module record and all eight process/source records, valid RECORD SHA256/size, and the existing frozen resource hashes before any socket or provider startup. Both drafts and compiled snapshots used for execution come from that bundle; a missing, foreign or tampered installed bundle fails without external-fixture fallback. This installed mode supports the documented wheel-only interpreter/venv data scheme. It does not infer installation from a path name.

External `--fixtures` still supplies raw injected inputs, the frozen resource manifest and post-execution legacy/development comparisons. Its copied process files are not installed execution inputs. `process_resource_origin` records the actual consumed resource paths, bytes and SHA256 values, distribution/module record and data root; `fixture_sha256` remains the separate external fixture accounting. Ordinary source-mode verification keeps consuming the frozen fixture resources and labels their origin `source_fixtures`, with no installed-distribution claim. This provenance is cooperative current-file evidence, not package-signature, historical-read or native-authority qualification.

The focused resource-origin tests use explicitly synthetic distribution/layout records and stop at a mocked provider boundary. They are regression controls, not a real wheel-only execution result. Installed verification requires a separately retained actual wheel build/install and verification run for the exact source/artifact tuple, including any later comparison integration.

Installed RECORD selection rejects unsupported internal path aliases across all received record paths before matching module/resources; valid leading parent runs into this distribution's `share/process-runtime/resources` data area remain supported. A leading-parent module spelling such as `../site-packages/process_runtime/__init__.py` is also rejected rather than ignored. This avoids a second canonical-equivalent module or resource entry hiding outside a raw suffix/exact-name count. This is lexical validation of the path representations supplied by the metadata API, with no extra arbitrary file-content reads.

Current-origin path checks reject module/resource leaf symlinks and resource ancestor aliases that change the exact anchored resolved resource location. A selected `sysconfig` data-root alias is supported when it resolves to the same real root and is reported as that real root; a broken or inconsistent foreign root fails. A module ancestor alias can pass only when the imported current module origin and exact distribution module record resolve to the same current file and RECORD checks pass; its reported module origin is resolved. None of these cooperative current-file checks attests what a historical import read, promises a hostile-filesystem snapshot, or changes source-mode provenance.
